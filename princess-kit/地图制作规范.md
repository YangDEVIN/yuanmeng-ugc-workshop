# 通用地图制作与验收规范

本规范适用于新建、复刻、导入和修改地图。设计尺寸、元件编号、角色资源与测试结论随项目交付，按当前场景实测填写。

## 设计与美术

- 先定义玩家目标、操作、反馈、胜负与重试流程。用可操作的 HTML 原型确定玩法、美术、镜头和交互，再映射到元梦。已有项目的局部修改沿用其工作流程。
- 先确认角色轮廓、场景比例、配色和照明，再选能还原这些特征的内置元件。对照原图检查远近景、侧面和背面。使用第三方资源时记录来源、许可及发布范围。
- 按材质设置颜色、纹理、光泽和透明度；普通改色球使用纯色材质。装饰随环境和功能成组布置，检查遮挡与重复。区分真实贴图、材质控制图、目录缩略图和预览代理。
- 共用图标、视角、走查与操作方式。以布局引导操作，保留必要的状态和错误信息。编辑页首次打开时与正式预览共享镜头、灯光、材质、天空和角色位置。

## 尺度、场景与路线

- 导出坐标使用厘米，注明坐标轴、原点和旋转约定。以当前角色实际包围盒和移动能力校准比例，逐处检查头部净空、通行宽度、台阶、斜坡与跳距。
- 地面、墙面、坡顶等连续结构尽量使用整件或缩放板。按高度和材质合并相邻区域，保留洞口、断层和上下层。检查封顶、接缝、吸附和碰撞。元件上限是预算，按导出的真实实例计数。
- 组合物件从一份布局推导各部分变换。检查支撑、轴心、相邻件和可操作区域。交互物件带稳定标识、触发条件、反馈和恢复逻辑；装饰避开通行空间。
- 从出生点到目标和出口逐段走查，在分岔处提供可辨识的引导。射击玩法保留原图阵营、出生朝向及 A/B 标记；剧情或跑酷玩法分别验证事件次序、着陆与复活。

## 2D 游戏、界面与输入

- 统一管理模拟时间、输入和胜负状态。布局适配视口及安全区，状态栏、角色层、操作层分别绘制。按实际显示尺寸检验精灵和文字清晰度。
- 帧动画按速度和游戏状态切换；地面、角色与障碍物共用投影、坐标和时间基准。复刻时记录采样精度、平台表现和已知差异。
- 按钮绑定目标控件，区分点击、按住和松开，验证鼠标、键盘及触屏。检查装饰层拦截输入、原生 HUD 遮挡、暂停恢复及焦点丢失。
- 先确认目标地图及编辑态，再创建 UI 和迁移 Lua。回读控件 UID 生成绑定表。计时、分数、动画和地图变化应有可观察的反馈。

## 数据、资源与还原

- 预览、编辑、导出使用同一布局数据；工程保留稳定的逻辑键、类型、变换、材质、交互信息与版本。导入旧工程时校验单位、类型、数量、尺寸和引用，保留无关元数据。
- 搜索内置目录后精确核对类型、原始尺寸、轴向、材质变体和偏心轴心。天空盒用真实显示 ID。分别标记目录资料、网页示意与编辑器实拍的证据。
- 资源包随附必要的图片、脚本、清单与启动入口。区分逻辑键、内置类型和每次导入生成的实例编号。自定义图片上传后回查素材库，控件使用返回的 assetName；运行时接口按各自签名处理。
- 读取当前会话状态、地图和图层，确认写入目标。写入前验证参数，记录批次、操作回执和实际实例。异步操作查询原操作 ID；不确定写入先回读。保存和脚本提交分别检查结果。
- 本机凭据只发送到指定的本机服务。线上预览和下载与本地写入分别说明。运行目录、认证、用户工程及没有公开授权的素材不随发布包分发。

## 本地 Agent 与交付验收

- 本地 Agent 在独立任务目录工作，装载本规范、格式契约及当前工程。工程内容按数据处理。应用结果前校验，用原草稿版本识别并发修改，保留恢复路径。
- 分别验证格式、截图、真实输入、玩法结果、日志和错误。保存后检查回读；试玩结束恢复编辑态及原采集设置。区分静态检查、单人和多人覆盖。
- 交付列明版本、入口、目标、已验证范围与待验证项。发布网页时检查资源引用、分享路径、缓存和部署结果。
